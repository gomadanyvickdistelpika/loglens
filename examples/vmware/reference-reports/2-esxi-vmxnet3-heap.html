Broadcom KB research (Matched from the LogLens KB library (research snapshot 2026-10-09, not a live search).)
Restarting ESXi management agents (related, matched by rule only): KB 320280 Restarting Management Agents in ESXi; KB 344682 ESXi host not responding or disconnected - VMware vSphere
Cause: Standard first action when hostd/vpxa are hung - but check for a storage or third-party cause first or the hang returns.
  1. Restart via the Host Client (Manage > Services) or SSH: /etc/init.d/hostd restart then /etc/init.d/vpxa restart; wait 1-2 minutes, confirm the host returns to Connected.
  2. Do not use services.sh restart / the DCUI option on hosts with shared graphics (vGPU/vDGA/vSGA).
  3. Before restarting check vSAN (esxcli vsan cluster get), LACP status and NSX VIBs.
  4. If SSH is unavailable or services keep hanging, cold reboot via iLO/iDRAC (avoid force reboot on vSAN hosts if a graceful shutdown is possible).
Host "Not Responding" in vCenter - heartbeat / vpxa binding (related, matched by rule only): KB 318647 ESXi host disconnects intermittently from vCenter Server; KB 399108 ESXi hosts intermittently show as "Not Responding" in vCenter Server due to vpxa heartbeat binding errors; KB 414524 ESXi Hosts Entering "Not Responding" State Every 60 Seconds Due to Incorrect UDP Port Configuration in vpxd.cfg; KB 306918 ESXi host disconnects from vCenter Server with the error: Agent can't send heartbeats because socket address structure initialization is failing
Cause: vCenter expects a UDP 902 heartbeat from each host (about every 10 s, 60 s window). Causes: stale management IP in the vCenter DB (vpxa bind Error 99), wrong VirtualCenterManagedIP, lost UDP 902 (firewall/ACL), wrong heartbeat port in vpxd.cfg (120 instead of 902), switch reboot, DNS failure.
  1. Wrong IP in VCDB: stop vpxd, correct the host entry in the database, start vpxd (use Broadcom guidance/support).
  2. Trace heartbeats: pktcap-uw on the host and tcpdump on vCenter to see where UDP 902 stops; check firewalls/ACLs.
  3. Check udp-port in vpxd.cfg is 902 (fix is on the vCenter side).
  4. Verify the host can resolve the vCenter name (getaddrinfo errors in vpxa logs).
  5. Last resort: remove the host from inventory and re-add it.
